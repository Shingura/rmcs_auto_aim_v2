# 自瞄项目结构

本文讲清楚自瞄由哪些部分组成、每部分在哪个文件、它们之间怎么串起来。读完你应该能定位任何一个环节在哪个文件。

## 一、自瞄不是一个程序，是五个组件

RMCS 通过配置里的组件列表加载自瞄，每个组件都能单独挂上或摘掉。

| 组件 | 干什么 | 文件 |
|---|---|---|
| `AutoAimComponent` | 自瞄本体，必需 | `src/component.cpp` |
| `AutoAimCapturerComponent` | 接海康相机出图 | `src/io/capturer/capturer.cpp` |
| `AutoAimRecorderComponent` | 录制相机和陀螺仪数据 | `src/io/recorder/recorder.cpp` |
| `AutoAimPlayerComponent` | 回放录制下来的数据 | `src/io/recorder/player.cpp` |
| `AutoAimVideoPlayerComponent` | 把本地视频当图像输入 | `src/io/recorder/video_player.cpp` |

两种典型组合：

- 实机：采集组件加自瞄本体，需要时再挂录制组件。
- 离线调试：视频播放组件或回放组件，加自瞄本体。

## 二、自瞄本体内部有两条线程

自瞄本体（`src/component.cpp`）不是一个循环，而是两条并行的工作线。

**算法线**跑在独立线程里，跟着相机走。每来一张图就干一轮活，实机上大约每秒 250 轮。它负责识别、位置解算、跟踪。

**控制线**就是 RMCS 的主线程，固定每秒 1000 次。它负责算提前量、决定开不开火、写输出。

两条线只交接一个东西：算法线算完产出的“要打谁、它在哪、往哪走”，控制线拿走用。

## 三、一次自瞄的完整链路

从相机出图到云台该指哪，一共九步。

1. **出图。** 采集组件把一帧图发出去。每帧还捆了一份“曝光那一刻云台是什么姿态”的数据。没有这份数据，后面算出的目标位置就是错的。
2. **进算法线。** 自瞄本体的输入回调存下最新一帧，唤醒算法线程（`src/component.cpp` 第 51 至 84 行）。
3. **拼相机位姿。** 用云台姿态加上相机装在车上的位置，算出相机此刻在世界里在哪、朝哪（`src/kernel/auto_aim.cpp` 第 122 至 134 行）。
4. **识别。** `src/kernel/detector.cpp` 调 `src/module/detector/armor_detection.cpp`，用一个神经网络模型一次性给出画面里所有装甲板的角点、颜色、兵种。能量机关走 `src/module/detector/rune.cpp`，前哨站和基地还要额外找绿灯。
5. **解算三维位置。** `src/kernel/pose_estimator.cpp` 配合 `src/utility/math/solve_pnp/`，把画面上的角点换算成现实里的位置和朝向。
6. **跟踪。** `src/kernel/tracker.cpp` 把观测喂给每个目标各自的模型（在 `src/module/tracker/model/` 下）。模型做滤波和预测，输出“这个目标现在在哪、往哪走、转多快”。然后 tracker 在这一步选出要打的那个。
7. **交接。** 算法线把选中的目标放进共享区，控制线取走。
8. **火控。** `src/kernel/fire_control.cpp` 算提前量和弹道，再判断能不能打中。
9. **写输出。** 把结果写到 `should_control`、`should_shoot`、`control_direction`、`robot_center` 这些接口上（`src/component.cpp` 第 341 至 348 行）。

## 四、跟踪和火控各自负责什么

这两个最容易混，分开说。

**tracker 干两件事。** 一是给每个目标维护一套状态，回答“它在哪、往哪走、转多快”；二是**在这些候选里选出要打的那一个**。第二件事就是我们要改的地方。

火控不参与选目标。它只拿到已经选好的那一个。

**火控干四件事：**

1. 算子弹飞过去要多久，再叠加两段延迟：发出开火指令到真打出去的延迟，以及图像从拍摄到进程序的延迟。
2. 让目标状态往前跳这么久，得到预测位置。
3. 解弹道，补上重力和空气阻力，算出云台该指向哪。这一步在 `src/module/fire_control/trajectory_solution.cpp`。
4. 判断此刻云台指的方向能不能命中，决定发不发弹。这一步在 `src/module/fire_control/shoot_evaluator.cpp`。

## 五、外部指令从哪来

自瞄不是完全自主的，它听几路外部指令。

**开不开自瞄，由人决定。** 鼠标右键或者遥控器右拨杆拨到上，自瞄才开（`src/component.cpp` 第 276 至 277 行）。开火意图同理，是鼠标左键或左拨杆拨到下。

**要打哪些兵种，可以被外部限定。** 组件参数里有一份白名单。另外导航模块可以下发“只打建筑”的指令，自瞄收到后就把候选限定成基地和前哨站（`src/component.cpp` 第 302 至 305 行）。

**打不打能量机关，导航模块也能下发**（`src/component.cpp` 第 284 至 285 行）。

**敌方颜色不用人操心。** 自瞄从裁判系统读自己的兵种，自动推出敌方是什么颜色（`src/kernel/auto_aim.cpp` 第 245 至 246 行）。

**哨兵有一处特殊处理。** 哨兵的自瞄是常开的，没有操控手去开关它，所以代码里单独给哨兵打开了“超时就解锁换目标”这个开关（`src/kernel/auto_aim.cpp` 第 248 至 249 行，注释写着“哨兵自瞄常开，需要超时检测”）。其他兵种这个开关是关的。

## 六、目录怎么分的

代码按四层摆放，作者写在 README 里。

- `src/kernel/`：运行时业务内核，和业务逻辑强相关。识别、位置解算、跟踪、火控、可视化都在这层。
- `src/module/`：可复用的算法模块，不含运行时逻辑，理论上能搬到别的项目。
- `src/io/`：采集和录制回放。
- `src/utility/`：和业务无关的基础设施，占了大头，有 99 个文件。数学、图像处理、ROS 2 封装、线程工具都在里面。

`src/component.cpp` 单独在最外层，是唯一入口。
